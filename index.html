How I work

  1. Measure first. I build a labelled test set before tuning anything, and change one thing at a time.
  2. Report what didn't work. My READMEs include the experiments that lowered a score and the limitations still open.
  3. Keep safety decisions deterministic. Where an error is costly, I put the rule in code and keep a person in the loop.
  4. Fix model bias in code, not in the prompt. A few lines of code fix skewed output more reliably than another instruction.
  5. Choose metrics that fit the problem. AUROC and calibration for imbalanced data, missed cases counted separately from false alarms.
  6. Ship it properly. An API, tests, a container and a README that states what the system is not for.
